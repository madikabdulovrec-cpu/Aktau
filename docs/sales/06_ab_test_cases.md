# A/B тест моделей: Claude vs GPT — методология

Как выбрать модель для бота, сравнив Claude и GPT на **одних и тех же** кейсах и **одном** системном промпте.

- **Набор кейсов:** [Тест-кейсы для бота.md](Тест-кейсы%20для%20бота.md) — 20 кейсов (TC-01…TC-20) на реальных диалогах из аудита. Отдельный набор не создаётся — единый источник.
- **Тестируемый промпт:** [05_bot_system_prompt.md](05_bot_system_prompt.md), Часть A.
- **Рабочая тетрадь для прогона:** [ab_test_scoring.xlsx](ab_test_scoring.xlsx).

## Два разных теста — не путать

| | Приёмочный тест | A/B тест моделей |
|---|---|---|
| Файл | [Тест-кейсы для бота.md](Тест-кейсы%20для%20бота.md) | этот документ + xlsx |
| Вопрос | «Бот вообще работает правильно?» | «Какая модель лучше — Claude или GPT?» |
| Объект | один бот | две модели на одном промпте |
| Оценка | бинарно: прошёл / не прошёл (✅) | балл 0-2 по 6 критериям |
| Когда | после каждой правки промпта | один раз, при выборе модели |

A/B тест берёт те же 20 кейсов, но вместо «прошёл/не прошёл» применяет балльную рубрику — иначе две хорошие модели неразличимы.

## Как проводить A/B тест

1. **Промпт.** Один и тот же системный промпт ([05_bot_system_prompt.md](05_bot_system_prompt.md), Часть A) — для обеих моделей. Модели: Claude Sonnet и GPT-4o. Параметры по возможности одинаковые (temperature ~0.5-0.7).
2. **Прогон.** Каждый из 20 кейсов TC-01…TC-20 подать боту (для кейсов с тредом — всю историю). Сохранить ответ дословно.
3. **Слепота.** Занести ответы в [ab_test_scoring.xlsx](ab_test_scoring.xlsx) как «Модель A» и «Модель B». Кто A, кто B — знает только организатор; для каждого кейса можно случайно менять местами. Оценщик баллов не должен знать, где какая модель.
4. **Оценка.** По каждому ответу — 6 критериев, шкала 0-2. Ориентир — раздел ✅ и «Эталон» соответствующего кейса. Суммы считаются автоматически.
5. **Раскрытие.** Свести суммы и критические провалы на листе «Итог», раскрыть модели.

Лучше, если оценщиков двое и независимо — потом усреднить.

## Рубрика оценки (6 критериев, 0-2 каждый)

| Критерий | 0 — провал | 1 — частично | 2 — отлично |
|---|---|---|---|
| **Релевантность** | Проигнорировал вопрос, ушёл в шаблон | Ответил, но не полностью | Точно ответил на то, что спросил клиент |
| **Краткость** | Простыня, шаблонное описание не по запросу | Длинновато, но терпимо | 1-2 коротких сообщения по делу |
| **Тон** | Робот / канцелярит / давление | Нейтрально, суховато | Тёпло, по-человечески, по имени |
| **Продвижение** | Тупик, нет следующего шага | Общий призыв «записывайтесь» | Конкретный шаг: точные слоты / нужное действие |
| **Возражение / edge** | Сомнение проигнорировано, спец-ситуация провалена | Отработал слабо | Снял сомнение / верно отработал handoff, противопоказание, язык |
| **Достоверность** | Выдумал факт / нарушил запрет | Мелкая неточность | Только факты из промпта, запреты соблюдены |

**Максимум:** 12 баллов за кейс, **240 за весь тест** (20 кейсов).

## Критический провал (red flag — фиксировать отдельно)

Независимо от баллов, отметить «да», если модель:
- выдумала цену, акцию или условие, которых нет в промпте;
- предложила Крио как доступную услугу (она отключена);
- начала продавать или считать стоимость курса (это работа мастера);
- солгала, что она живой человек, на прямой вопрос;
- не поставила тег `[[BOOKING]]` / `[[HANDOFF]]` там, где он обязателен;
- ответила не на языке клиента (TC-20).

Модель с критическими провалами не должна побеждать, даже если набрала больше баллов.

## Пробелы: 5 кейсов, которые стоит добавить в набор

20 кейсов покрывают воронку хорошо, но 5 ситуаций не охвачены. Рекомендую дописать их в [Тест-кейсы для бота.md](Тест-кейсы%20для%20бота.md) — тогда A/B-набор станет 25 кейсов (макс 300).

| Предлагаемый кейс | Входящее | Почему важно |
|---|---|---|
| **«Вы бот?»** | «Это бот или живой человек?» | Промпт требует честного ответа. Не проверяется ни одним TC. |
| **Запрос на Крио** | «Хочу крио, сколько стоит?» | Крио отключено. Риск, что модель предложит его как доступное — это критический провал, и его надо ловить. |
| **Услуга вне каталога** | «А наращивание ресниц делаете?» | Проверка дисциплины «не выдумывай» на услуге, которой нет вообще. |
| **Раздражённый клиент** | «Вы вообще отвечаете?! Жду второй день!» | Тёплое восстановление контакта vs шаблонное оправдание. |
| **Реанимация после молчания** | Клиент замолчал 3 дня назад — нужно касание | Это 4-я точка обрыва из аудита («пустой дожим»). В 20 кейсах не охвачена — а проблема ключевая. |

Реанимация — самый важный пробел: аудит прямо разбирает «дожим пустой» как одну из 4 причин потери лидов, а среди TC её нет.
