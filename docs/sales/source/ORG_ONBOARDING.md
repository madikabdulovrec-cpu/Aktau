# Онбординг организации — как подключить скин и включить фичи

Практический гайд: завести организацию, дать ей ассистента (скин), включить
пункты меню. Всё делается **в админке** `komekai.evimiz.ai`, файлы руками
в папки не кладутся.

## Модель в двух словах

```
Организация ──имеет──> Скин ──содержит──> Tools ──дают──> Features (пункты меню)
```

- **Организация** (clinic) — клиент. Видна в свитчере слева сверху.
- **Скин** — конфиг ассистента: приветствие, FAQ, цены, голос, набор tools.
- **Tools** — инструменты ассистента (запись, расписание, проверка сотрудников…).
- **Features** — какие пункты меню показываются. Вычисляются из tools скина:
  | Tool в скине | Пункт меню |
  |---|---|
  | `get_doctor_schedule` | Расписание |
  | `verify_partner_employee` | Партнёры |
  | `add_to_night_queue` | Заявки |
  | `book_appointment` | booking-флоу |

Нет скина у организации → features пустые → soft-пункты меню скрыты.

## Шаг 1 — создать организацию

Свитчер организаций (слева сверху) → **«+ Новая организация»** → заполнить
id и название. Доступно platform_admin.

## Шаг 2 — дать организации скин

Переключись на новую организацию в свитчере, открой **«Настройки ассистента»**.
Два пути:

### Путь А — импорт готового YAML (быстро)

Если есть готовый скин-файл `.yaml`:
1. «Настройки ассистента» → кнопка **«Импорт YAML»** (видна platform_admin).
2. Выбрать `.yaml`-файл — он **загружается через эту кнопку**, не кладётся
   ни в какую папку. Импорт раскладывает YAML в БД-блоки активной организации.
3. Формат файла — как `skins/_template.yaml` в репозитории (шаблон с
   комментариями по всем секциям). `skins/_default.yaml` — нейтральный пример.

### Путь Б — собрать в UI с нуля

В «Настройках ассистента» секции **Greeting / Voice / FAQ / Prices /
Services** — заполнить вручную. Скин создаётся сразу в БД.

## Шаг 3 — включить tools → появятся пункты меню

«Настройки ассистента» → секция **Tools** — чекбоксы по инструментам.
Включаешь нужный (напр. `get_doctor_schedule`) → после перезагрузки
страницы соответствующий пункт меню («Расписание») появляется.

## Важные нюансы

- **Импорт / Skin Editor — только platform_admin.** Owner редактирует
  существующий скин, но импорт YAML — за супер-админом.
- **db-source vs yaml-source.** Импорт и редактирование в UI создают
  **db-скин**. Чтобы голосовой ассистент реально начал говорить по нему,
  у организации `skin_source` должен быть `db` (переключается отдельно —
  `PATCH /api/clinics/<id>`). Для пунктов меню достаточно самого скина.
- **Файлы скинов в репозитории** (`skins/<client>.yaml`) — это legacy
  yaml-source путь (так живёт НЕЙРОН на своей ветке). Новый клиент
  подключается через UI-импорт, без коммита файла в репо.
- Изменения скина применяются на лету (Redis reload) — следующий звонок
  слышит новый скин, под рестарта не нужно.
