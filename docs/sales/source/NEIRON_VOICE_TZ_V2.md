## Задачи V2 (по приоритету)

### 1. QA скин-нейтральной Алии — КРИТИЧНО, первым делом

Код стал multi-skin, но **на звонке это ещё не проверено**. Нужно убедиться,
что только что влитая работа реально живёт:
- прозвонить скин `_default` (нейтральный «Помощник») — Алия здоровается,
  прощается, реагирует на тишину **фразами из скина**, не падает;
- прозвонить `medical_neiron` — поведение НЕ изменилось после рефакторинга
  (регрессия-чек);
- проверить, что числа/телефоны в ответах звучат естественно
  (`text_normalize` отрабатывает на обоих скинах);
- голос берётся из `voice.*` скина, а не дефолтный.

Результат — короткий лог QA в `neiron` (что прозвонено, что услышал, баги).
Любой найденный баг ядра → PR в `main`.

### 2. Де-хардкод «Алия»/«Пациент» в `call_analyzer.py`

`gateway/.../call_analyzer.py` зашивает имена «Алия» и «Пациент» в разбор
транскрипта. Брать из `skin.assistant.name` (и нейтральное «Клиент» как
фоллбэк). Дёшево, доводит neutrality-историю до конца. → PR в `main`.

### 3. Подготовка NEIRON → db-source

Скин НЕЙРОНа уже импортирован в DB-скин-систему (clinic `neiron`, 18 блоков),
но `skin_source` пока `yaml` — гейтвей читает YAML-файл, не блоки.
- выверить импортированные блоки в админке (greeting/FAQ/цены/голос/tools) —
  совпадают ли с `medical_neiron.yaml`;
- если расхождения — поправить блоки в UI;
- подготовить чеклист «что проверить после флипа на `db`».

⚠️ Сам **флип `skin_source=db` — решение и действие владельца**, не твоё.
Твоя часть — чтобы к моменту флипа db-скин был выверен и эквивалентен YAML.

### 4. Язык ru/kz по ходу звонка

Сейчас язык звонка статичен — определяется по ответу LLM, не по реплике
клиента. Нужно: клиент заговорил на казахском — Алия переключается на kz
(STT-язык, TTS-голос, язык промпта). → PR в `main`. ~0.5 сессии.

### 5. Реальный STT confidence

`yandex_stt.py` ставит фиктивные `0.9` — ветка low-confidence мертва, скин
никогда не просит переспросить. Пробросить реальный confidence из ответа
SpeechKit. → PR в `main`. ~2 ч.
