# HANDOFF — бот M&M на message.help (точка входа для новой сессии)

> Этот файл — стартовая точка для новой Claude-сессии, продолжающей работу над
> ботом. Память предыдущих сессий локальна и в репозиторий не попадает — поэтому
> весь нужный контекст собран здесь. **Прочитать первым.**
>
> Дата подготовки: 2026-05-22.

## Что за проект

Бьюти-студия **M&M Fabrica** (Алматы, ул. Ауэзова 175Б; коррекция фигуры и
косметология). Делаем **бота первичной обработки заявок**: клиент пишет в
WhatsApp → бот мгновенно отвечает, доводит до записи на бесплатную консультацию,
передаёт менеджеру. Цель — перестать терять заявки на входе воронки (аудит
`docs/sales/audit.html`: до консультации доходит лишь 7% обращений).

## Архитектура — решено

Бот = **интеграция к CRM message.help** (вариант, выбранный владельцем).
Студия ведёт WhatsApp и отдел продаж внутри CRM message.help; бот цепляется к ней
вебхуком. Прошлые подходы — Cloudflare-прототип на Wazzup (`worker/mm-bot.js`) и
вариант на платформе KomekAI — **отброшены**, остаются как legacy.

## Ограничения (от владельца) — соблюдать

- Один номер WhatsApp.
- Бот отвечает ТОЛЬКО новым лидам, действующих клиентов не трогает.
- Бот замолкает, как только в чат подключился сотрудник.
- Бот в Altegio **только читает** (история клиента, свободные слоты) — записей НЕ
  создаёт; фиксацию записи в Altegio делает менеджер.

## Что уже сделано

**`worker/mh-bot.js`** — Cloudflare Worker, бот message.help. Реализовано:
- приём вебхука `channel.message.created`; обрабатываются только сообщения клиента
  (`destination=from`); эхо-защита своих сообщений по id;
- гейт «только новые лиды»: пауза при подключении сотрудника (`from_operator` /
  `contact_in_work`, 7 дней) и после своего handoff/booking; проверка действующего
  клиента по истории визитов Altegio (опционально);
- ядро Claude: вызов с кэшем системного промпта, история диалога в KV, дедуп,
  retry + мягкий fallback при сбое;
- анти-галлюцинация: жёсткие разделы промпта «работай только с тем, что дано» и
  «всегда в роли», `temperature` 0.3;
- отправка ответа через `send_message`; handoff — назначение чата менеджеру
  (`updateOperator`);
- слоты на консультацию — реальные из Altegio (`book_dates`/`book_times`, только
  чтение, кэш 10 мин), фоллбэк на график.

**`worker/wrangler-mh-bot.toml`** — конфиг деплоя.
**`worker/MH_BOT_SETUP.md`** — пошаговая инструкция развёртывания.
**`docs/sales/05_bot_system_prompt.md`** — системный промпт (синхронизирован с кодом).

Синтаксис `mh-bot.js` проверен (`node --check`). Код **в проде не тестировался**.

## Следующий шаг — деплой (задача не выполнена)

Делать по **`worker/MH_BOT_SETUP.md`**. Понадобится:
1. Доступ к API message.help — логин/пароль аккаунта `medstarcompany@mail.ru`
   (бот логинится сам), подтвердить `project_id` (предположительно 220763) и
   `uuid` WhatsApp-канала.
2. Выключить встроенный англоязычный меню-бот message.help (иначе два бота).
3. (Опц.) токены Altegio — для гейта и реальных слотов. Без них бот работает.
4. `wrangler deploy`, регистрация вебхука в message.help, боевой тест.

## VERIFY — проверить на первом боевом тесте

Эти места написаны по спецификации message.help/Altegio и в коде помечены
комментарием `VERIFY` — подтвердить на реальных данных:
- формат вебхука `channel.message.created` (в коде есть лог `RAW_WEBHOOK`);
- `send_message` с `destination=from_operator` — доходит ли ответ клиенту;
- возвращает ли message.help наши исходящие сообщения вебхуком (эхо-защита);
- `get-user` — точное поле телефона клиента;
- `contact_by_phone` — поле `id` контакта;
- Altegio: `clients/search`, `book_dates`/`book_times`, id услуги-консультации.
